# Expense Tracker using Data Science

An educational expense tracker with an interactive browser dashboard, synthetic transaction data, Python analysis scripts, charts, and portfolio guidance.

## Run & Operate

- `pnpm --filter @workspace/api-server run dev` — run the API server (port 5000)
- `pnpm --filter @workspace/expense-tracker run dev` — run the expense tracker dashboard
- `pnpm --filter @workspace/expense-tracker run typecheck` — typecheck the dashboard
- `pnpm run typecheck` — full typecheck across all packages
- `pnpm run build` — typecheck + build all packages
- `pnpm --filter @workspace/api-spec run codegen` — regenerate API hooks and Zod schemas from the OpenAPI spec
- `pnpm --filter @workspace/db run push` — push DB schema changes (dev only)
- Python learning project lives in `artifacts/expense-tracker/project/`; install its `requirements.txt`, then run `python main.py` or `streamlit run app.py`.
- The browser dashboard uses local storage and synthetic examples; it does not require a database or API credentials.

## Stack

- pnpm workspaces, Node.js 24, TypeScript 5.9
- API: Express 5
- DB: PostgreSQL + Drizzle ORM
- Validation: Zod (`zod/v4`), `drizzle-zod`
- API codegen: Orval (from OpenAPI spec)
- Build: esbuild (CJS bundle)

## Where things live

- `artifacts/expense-tracker/src/` — browser dashboard and UI
- `artifacts/expense-tracker/project/` — Python pipeline, optional Streamlit app, sample CSV, and student-facing README
- `lib/api-spec/openapi.yaml` — shared API contract (the expense tracker currently uses no API)

## Architecture decisions

- Keep the first version self-contained: browser transactions persist in local storage, while the Python pipeline reads and writes CSV files.
- Use synthetic example data rather than asking for real financial records or connecting to a bank.
- Treat dashboard observations as descriptive examples, not personalized financial advice.

## Product

Users can inspect, filter, add, edit, import, and export transactions, then view category and time-based spending summaries. Student materials explain data preparation, analysis, GitHub publishing, screenshots, and interview discussion.

## User preferences

The project should be beginner-friendly and professional, suitable as evidence for data analyst, business analyst, and financial analyst internships or placements.

## Gotchas

- Browser local storage is isolated to the current browser and does not sync to the optional Python/Streamlit project.
- Python-generated reports are written to the selected output folder and can be regenerated by rerunning `main.py`.
